# Working electrical interface

This documents the **active transmit wiring that worked on one FV-16VEC1S with
an ESP32-S3**. It does not establish that every Panasonic connector, ERV revision
or ESP board has the same voltage levels.

Print [wiring.pdf](wiring.pdf) at actual size, or view [wiring.svg](wiring.svg).
The drawing is generated by `tools/draw_wiring.py`, so it can be updated without
editing a screenshot. GPIO numbers identify signals, not header-pin positions.

## Parts and connections

| Part | Value / role |
|---|---|
| R1 | 2.2 kΩ, 1%, ¼ W: ERV TX to ESP RX node |
| R2 | 4.7 kΩ, 1%, ¼ W: ESP RX node to common ground |
| R3 | 1.0 kΩ, 1%, ¼ W: ESP TX to ERV RX |
| JP1 | Optional removable link in the transmit path |
| ESP | ESP32-S3 tested on hardware with the earlier standalone firmware |
| Power | ESP USB power adapter; ERV uses its normal supply |

```
ERV TX ───── R1 2.2k ──────┬──────── ESP RX (example GPIO16)
                           │
                         R2 4.7k
                           │
ERV GND ──────────────────┴──────── ESP GND

ERV RX ───── JP1 ───── R3 1.0k ───── ESP TX (example GPIO17)

ERV 12V ─── NO CONNECTION to ESP
OEM controller TX ─── DISCONNECTED from ERV RX
ESP power ─── USB
```

**TX/RX labels above are from the ERV's perspective.** Identify the actual
signal direction on your connector. In the original bench investigation,
reversed RX/TX initially produced valid-looking outgoing bytes but no response.
Do not use connector position, wire color, or another model's pinout as proof.

## Why these resistor values

The observed ERV transmit high level was approximately **4.16–4.48 V**.
The observed OEM controller transmit high level was approximately **6.5–6.72 V**.
These are different electrical domains; both exceed a bare 3.3 V GPIO input.

With no internal pull, the R1/R2 divider gives:

`V_RX = V_ERV_TX × 4.7 / (2.2 + 4.7)`

That is approximately **2.83–3.05 V** over the measured ERV range. The working
firmware enabled the ESP RX internal pull-down. With a nominal 45 kΩ pull-down,
R2's effective resistance is `4.7k || 45k ≈ 4.26k`, giving approximately
**2.74–2.95 V**. Internal pull resistance is not a precision resistor; these
are nominal calculations, not guaranteed limits.

For the ESP32-S3 at 3.3 V, the datasheet input-high minimum of 0.75 × VDD is
2.475 V. Consult the [ESP32-S3 datasheet](https://documentation.espressif.com/esp32-s3_datasheet_en.pdf)
and the datasheet for your exact MCU. Verify the actual loaded RX waveform,
high/low margins and overshoot before attaching the ESP. At **6.7 V**, this
2.2k/4.7k divider would put the node above 4.4 V and is unsuitable.

The component defaults `rx_pull_down: true` and reapplies that pull mode after
ESPHome configures the UART. This avoids an unintended UART RX pull-up changing
the divider behavior. `rx_pull_down: false` disables both internal pulls; use
it only with an interface designed/measured for that loading. Classic ESP32
input-only pins without pull resistors are rejected when this option is true.

## Transmit path

The tested ESP's 3.3 V output, through R3, produced roughly **3.1 V** on ERV RX
and successfully carried polls and captured control commands after direction
was corrected. A 5 V buffer was therefore not required on that unit.

R3 limits current; it is **not** a voltage translator, clamp, or galvanic
isolator. The OEM controller's TX must not remain connected in parallel with
the ESP output. The component expects to be the only transmitter driving ERV
RX. The standard ESPHome UART keeps TX assigned to the UART, idling low under
inversion. This ESPHome implementation has not yet been hardware-tested.

This is positive-voltage, inverted UART signaling, not evidence of RS-232
voltage levels or RS-485 differential signaling. Do not substitute those
transceivers merely because the interface is serial.

## Board and pin selection

The full YAML uses GPIO16 RX and GPIO17 TX as **examples**, configured under
`uart:`. The library has no hard-coded GPIO numbers. Pick pins supported by your
board and ESPHome's validation, and account for boot strapping, onboard devices,
USB, flash and PSRAM. For example, some ESP32 modules reserve pins 16/17 for
PSRAM; the classic ESP32 compile test is not a wiring recommendation for every
ESP32 module.

The dedicated UART uses **4800 baud, 8E1**, with **both pins inverted** for the
measured idle-low bus. The divider does not invert the signal. If a different
external interface introduces inversion, the UART polarity must match the
resulting signal; only the illustrated passive divider/direct transmit interface
was verified in the bench setup. Baud/framing are validated as 4800/8E1.

## Assembly and first power-up

1. Power down the ERV and ESP before wiring. Verify the connector directions
   and common ground with the original controller and a scope as appropriate.
2. Disconnect the OEM controller TX from ERV RX. Remove the earlier passive
   sniffing tap from GPIO17 if one was installed; GPIO17 is now a transmitter.
3. Assemble R1/R2 and check the RX node voltage/waveform before connecting it to
   the ESP. Connect the shared ground and R3 transmit path.
4. Power the ESP by USB. Leave the ERV's 12 V terminal unconnected to the ESP.
5. Only when ready for device installation, use the documented YAML and verify
   that the board, pins, inversion and pull setting match your assembly.
6. After installation, check `connected`, valid-frame count and fault code
   before using mode/preset controls. The initial expected behavior is polling
   and readback, not a forced On/Off state change.

## Recovering the original controller

Power down both devices. Disconnect the ESP transmit path before reconnecting
the OEM controller TX to ERV RX. Restore the original wiring and power up the
ERV/controller. Preserve the original connector labeling to make reversal easy.

A **passive two-channel sniffer** is a separate wiring/firmware configuration.
The earlier capture used a 4.7k/3.3k divider for the approximately 6.7 V controller
line and two RX inputs. That circuit is not the active interface in this repo;
never connect the controller's high-voltage transmit line to the ESP TX output.
